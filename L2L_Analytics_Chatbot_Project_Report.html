1. Executive Summary & Purpose

The L2L Analytics Chatbot is an enterprise-grade AI conversational platform specifically built for manufacturing operations and maintenance analysis. It enables plant supervisors, reliability engineers, and operational leaders to query Leading2Lean (L2L) dispatches, machine downtime, and technician work orders using intuitive natural language.

Rather than relying on manual dashboard filtering or slow ad-hoc SQL against cloud databases, the system translates conversational questions into optimized local DuckDB SQL queries, generates responsive Plotly visualizations, and maintains full conversational memory across sessions.

⚡ Sub-Second Analytics

Columnar DuckDB local database cache eliminates BigQuery latency, delivering near-instant query results.

📊 Dynamic Visualizations

Automated Plotly bar, line, pie, and scatter charts generated directly by the LLM from SQL outputs.

💾 Persistent Checkpoints

PostgreSQL 16 PostgresSaver keeps multi-turn conversational history and charts intact across reloads.

🔌 Protocol Ready

FastMCP server exposes database tools via Model Context Protocol for external IDEs and agents.

2. System Architecture & Workflows

A. Two-Tier Data Strategy (BigQuery → Local DuckDB)

Direct LLM querying of cloud data warehouses like Google BigQuery can be costly, slow, and prone to strict rate limits. The project resolves this by caching the analytical dataset locally:

  • Sync Pipeline (src/cache.py): Queries cons_kamos_l2l.f_l2l_dispatches in Google BigQuery, standardizes timestamp types, and materializes the local table f_l2l_dispatches inside /app/data/l2l_analytics.duckdb.
  • Safe Execution (run_duckdb_safely): Opens connections in read-only mode with a strict 10s statement timeout and 2GB maximum memory limit.
  • API Hook: Ingestion can be refreshed on demand via POST /sync-cache.

B. LangGraph Cyclic ReAct Graph (src/agent.py)

The core intelligence is driven by a LangGraph StateGraph coordinating autonomous tool execution:

  • Agent Node: Receives user messages, formats prompt with calendar/schema context, and invokes the model with bound tools.
  • Conditional Routing: Inspects model outputs; if tool calls are present, routes to the tools node; otherwise routes to END.
  • Tools Node: Executes either query_l2l_database (for tabular answers) or generate_l2l_chart (for Plotly visualizations), feeding results back into the conversation state.

C. Hypermedia Frontend Architecture (FastAPI + HTMX + Tailwind)

The web UI eliminates the complexity of separate React/Vue build pipelines by adopting modern hypermedia controls:

  • Partial Swaps: Submitting a question posts via HTMX (hx-post="/chat") and streams back a partial HTML response (chat_response_partial.html) appended directly to the chat log.
  • Out-Of-Band (OOB) Updates: Automatically updates the chat header and active session ID without re-rendering the whole page.
  • Sidebar Reactivity: Emits an HX-Trigger: refreshSidebar header so active session titles appear instantly in the sidebar navigation.
  • Plotly Replay: src/utils/helpers.py reconstructs past session turns so historical charts re-render interactively when browsing older threads.
